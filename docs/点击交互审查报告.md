# 点击交互审查报告

> 审查日期：2026-10-15
> 对比对象：Melodia（`/home/rocky/code/Melodia`，Kotlin Compose Multiplatform，继承来源项目）
> vs Siren（本仓库，`crates/siren-app`，Rust + GPUI）
> 范围：两项目桌面端界面中"**文字本身可点击并触发页面跳转**"的全部位置（不含按钮图标、不含纯行为操作）。

---

## 结论摘要

Melodia 的"文字即链接"是系统性设计：全局复用 `TrackRow` 的行内链接组件
（`artistLinks` / `albumLink`，被歌单页、专辑页、歌手页、搜索单曲 tab、曲风详情、最近播放 6 处复用），
加上 `DesktopNavigator` 统一跳转入口（`ui/shell/DesktopNavigator.kt:11-37`），
歌手名 / 专辑名 / 昵称等元信息文字在几乎所有界面都可点击跳转。

Siren 目前全项目仅有一处"文字点击跳详情"（正在播放来源标题，`now_playing.rs:236-268`），
其余界面均为"整行点击 = 播放，行内文字是死区"。导航出口齐全
（`Root::open_playlist/open_album/open_artist/open_profile`，`ui/mod.rs:763-819`），
差距集中在**没有把这些入口接到文字上**，以及少量模型字段缺失。

## 二、Siren 现状盘点

关键数据前提：

- `Song`（`siren-core/src/model/mod.rs:17-31`）有 `artist_ids: Vec<i64>`，**无 `album_id`**
- `Album` / `AlbumDetail` 只有拼接的 `artists` 字符串，**无歌手 ID**
- 导航出口齐全：`PageEvent::{OpenPlaylist,OpenAlbum,OpenArtist,OpenProfile}` + `Root::open_*`
- 唯一"文字点击跳详情"范例：`source_title`（`now_playing.rs:236-268`），可作补做模板

| 界面区域 | 状态 | 明细 |
|---|---|---|
| 标题栏 | 部分 ✅ | 搜索框、菜单项（个人主页/最近播放/设置/账号设置）可点；菜单头部昵称不可点（设计如此） |
| 底部播放条 | ❌ | 歌名（player_bar.rs:67-72）、歌手（:73）、封面（:32,59）全不可点 |
| 正在播放详情 | 部分 | 来源标题 ✅；**歌名/歌手 ❌、评论昵称 ❌、歌手专辑卡专辑名 ❌、相似歌手卡 ❌** |
| 队列面板 | ✅ | 行点击=播放，无跳转需求（与 Melodia 一致） |
| 歌单详情页 | 部分 | 整行=播放 ✅；**创建者昵称 ❌（creator_id 现成）、曲目行歌名/歌手/专辑列 ❌** |
| 专辑详情页 | 部分 | 整行=播放 ✅；**艺术家行 ❌（模型无歌手 ID）、曲目行内文字 ❌** |
| 歌手详情页 | ✅ | 专辑行 → OpenAlbum、相似歌手行 → OpenArtist 均已实现 |

| 最近播放 | 部分 | 卡片 ✅；**歌曲行内文字 ❌** |

## 三、差距清单（Melodia 有、Siren 无）

### 按界面区域

| 区域 | Melodia 的文字点击 | Siren 现状 | 差距 |
|---|---|---|---|
| 底部播放条 | 歌手名（多歌手各自可点）→ 歌手页 | 全不可点 | ❌ 全缺 |
| 正在播放详情 | 歌词页歌名→专辑、歌手→歌手、详情卡专辑行、关于艺人、更多专辑、相似艺人 | 仅来源标题可点 | ❌ 大部分缺 |
| 歌单详情页 | 创建者昵称→主页、曲目行歌手→歌手、专辑→专辑 | 创建者昵称不可点；行内文字全不可点 | ❌ 缺 |
| 专辑详情页 | 曲目行歌手/专辑链接 | 行内文字不可点；艺术家行不可点（模型限制） | ❌ 部分缺 |
| 搜索页 | 单曲行歌手/专辑链接、**歌手行→歌手页**、右键查看歌手 | 歌手行整行不可点；单曲行内文字不可点 | ❌ 缺（最严重） |
| 评论面板 | 评论者昵称→其主页 | 不可点 | ❌ 缺 |
| 个人主页 | 关注/粉丝统计→FollowList 页 | 无 FollowList 路由 | ❌ 路由缺失 |
| 最近播放 | 歌曲行歌手/专辑链接 | 行内文字不可点 | ❌ 缺 |
| 首页 | 曲风色块→Style 详情 | 无 Style 路由 | ❌ 路由缺失 |
| 队列面板 | 也不可点跳转 | 行点击播放 | ✅ 无差距 |
| 歌手详情 / 音乐库 / 收藏弹层 | 可点 | 已对齐 | ✅ |

### 非路由类差距

- 右键菜单"复制链接 / 复制歌曲信息"：Melodia 遍布曲目/歌单/专辑/电台，Siren 无此类项
- "在网易云中搜索"外部平台搜索：Siren 无
- 播客/电台生态整体（Radio / PodcastCategory / PodcastToplist 等路由与点击）：Siren 功能未落地

## 四、修复成本分层

### 低成本（数据已在手，加 `on_click` + `PageEvent` 即可）

写法模板参照 `now_playing.rs:236-268`（`source_title`）；行内文字与整行"点击播放"
共存时用 `stop_propagation`，参照 `like.rs:38` / `home.rs:447`。

1. **搜索页歌手结果行整行 → OpenArtist**（`search.rs:406-424`，已知缺陷 K3，最严重）
2. **歌单详情创建者昵称/头像 → OpenProfile**（`PlaylistDetail.creator_id` 现成，`playlist.rs:903-920`）
3. **正在播放：歌手专辑卡专辑名 → OpenAlbum、相似歌手卡 → OpenArtist**（`now_playing.rs:488-547`，数据在手）
4. **各曲目行歌手列 → OpenArtist**（`Song.artist_ids` 现成；涉及 playlist/album/search/recent/queue 五处）

### 中成本（需小改模型）

5. 曲目行专辑列 → 给 `Song` 加 `album_id`
6. 专辑详情艺术家行 → 给 `AlbumDetail` 加 `artist_ids`
7. 评论昵称 → 主页，确认/补齐 `CommentItem.user` 的 uid
8. 底部播放条点击交互（建议封面点击展开正在播放详情，对齐 Melodia PlayerBar.kt:125）

### 结构性差距（设计层面）

9. **多歌手逐个点名跳转**：Melodia 用 `LinkAnnotation` 渲染多个独立链接；Siren 的 `Song.artists`
   是 `/` 拼接字符串，对齐需改为按 `artist_ids` 数组生成多段文字
10. `FollowList` / `Style` / 电台播客路由整体缺失（功能未落地，超出点击交互范围）

## 五、建议实施顺序

1. 低成本 1-4：一个模板四处复用，一次提交即可覆盖搜索/歌单/正在播放三个界面
2. 中成本 5-8：先扩模型（`Song.album_id`、`AlbumDetail.artist_ids`、`CommentItem.user.uid`），再统一补行内文字
3. 右键菜单补"复制链接/查看歌手/查看专辑"（顺带对齐 Melodia 上下文菜单）
4. 结构性项随对应功能（FollowList、Style、播客）落地时一并处理
