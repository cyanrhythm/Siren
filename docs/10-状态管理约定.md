# 状态管理约定

> 上游规范：`.opencode/skills/gpui-kit/references/coding-guides.md` 的
> **State ownership** 与 **Avoid state feedback loops**。本文是其在 Siren 的落地细则。
>
> 关联：[`01-架构设计.md`](01-架构设计.md) §4 数据流、[`ISSUE.md`](ISSUE.md)。

## 1. 原则

1. **单一真源**：任一数据只在一个 owner 中保存；其它位置只读（或经事件请求变更）。
2. **窄化 owner**：把状态放在能保持其正确的最小 owner 中。
3. **单向数据流**：用户操作 → 指令 → owner 更新 → 订阅者重绘；回调只表达意图，不写第二份状态。
4. **显式持久化归属**：需要落盘的键归属于一个明确的 store，不得散落。

## 2. Owner 层级

| 层 | 载体 | 承载 |
|---|---|---|
| 共享服务 | GPUI Global | `SettingsStore`、`Session`（账号）、（只读）`Theme` |
| 领域服务 | `Entity<T>`（如 `Playback`） | 播放状态、队列、歌词/详情等播放域数据 |
| 外壳 | `Entity<Root>` | 仅编排：导航栈、页面实体句柄、浮层开关 |
| 页面 | `Entity<XxxPage>` | 该页面的数据与瞬态视图状态 |
| 组件 | GPUI keyed state / `*State` 实体 | 输入框、滑块等可复用行为状态 |

规则：

- **页面/组件不得依赖 `Root` 类型**；需要外壳协作时 `cx.emit(PageEvent)`，需要共享能力时依赖 `Services`。
- **外壳不保存页面数据**；页面自带数据（如搜索结果、歌单详情）。

## 3. 单一真源规则

- 同一语义的值**只在一处存储**，其它读取方通过该 owner 读。
- **禁止**为同一值维护"镜像字段 + 手工同步"（例：`Root.account` 与 `LibraryPage.nickname`）。
- 需要跨层显示时，**订阅** owner，而不是复制。
- 变更必须**同时更新构成一个不变量的全部字段并只 `notify` 一次**。

## 4. 全局 store

以 GPUI `Global` 承载跨页面共享的应用级状态：

```rust
pub(crate) struct SettingsStore { data: siren_core::settings::Settings }
impl Global for SettingsStore {}

impl Root {
    fn new(/* .. */) {
        // 启动时装载一次
        cx.set_global(SettingsStore::load());
    }
}

// 读取（&App / Context 均可，自动解引用）
let q = cx.global::<SettingsStore>().quality();
// 变更（写入并落盘）
cx.global_mut::<SettingsStore>().set_quality(q);
```

- **读**：`cx.global::<G>()`；**写**：`cx.global_mut::<G>()`（写入方法内部负责持久化）。
- 需要跨实体响应全局变化时用 `cx.observe_global::<G>(...)`；仅本实体响应则直接 `cx.notify()`。
- **例外**：窗口位置/大小在 UI 图建立之前读取（`siren-app/src/lib.rs::run`），
  故仍用 `settings::{load,save}_window_bounds` 引导期自由函数，与 store 共用同一文件。

## 5. 数据流与事件

| 场景 | 手段 |
|---|---|
| 页面请求导航/外壳动作 | `cx.emit(PageEvent::…)`，外壳 `subscribe` 处理 |
| 跟随某实体生命周期订阅其变化 | `cx.observe(&entity, …)` |
| 订阅事件 | `cx.subscribe(&entity, …)`（保存返回的 `Subscription`） |
| 跨实体响应全局 | `cx.observe_global::<G>(…)` |
| 受控输入/选择 | 传入当前值 + 回调表达意图，owner 更新后重绘 |

**禁止**：

- 在 `render` 中无条件 `cx.notify()` 或发起网络请求（副作用）。
- 把 owner 下发的值经用户回调再回灌（反馈环）。同步时比较一致快照或区分来源。
- 把 `EntityId` 建在可变列表下标或易变标签上。

## 6. 异步与取消

- 页面/实体发起的异步任务必须能在**被新的同类请求取代**时失效：
  为每个可重入的异步流程引入 **generation 计数**，回调先比对代数再写入。

```rust
self.reload_gen += 1;
let gen = self.reload_gen;
cx.spawn(async move |this, cx| {
    let data = fetch(..).await;
    this.update(cx, |this, cx| {
        if this.reload_gen != gen { return; } // 已被更新的请求取代
        this.apply(data, cx);
    }).ok();
}).detach();
```

- 能返回 `Task` 的 API 优先保存 `Task` 以支持取消；`detach()` 仅用于确实"发射后不管"且已自行判代的流程。
- 失败路径必须记录（`log::warn!/error!`），不得静默 `let _ = …`。

## 7. 元素（Element）id 约定

GPUI 的 `GlobalElementId` 是**当前 view 内 id 栈的哈希**，而 a11y 树要求一帧内节点 id 唯一：
同一 view 内 id 路径相同的两个元素会触发 `Duplicate a11y node id` 断言——**debug 构建直接 panic**
（表现为窗口一出现就崩溃），release 构建则静默丢弃该节点（无障碍失效）。约定：

1. **每张卡片 / 每个面板的容器都要有 id**（如 `.id("np-card-lyrics")`、`.id("shell-player-bar")`），
   为内部交互元素提供命名空间。否则两张同类卡片同帧渲染时，卡内按钮的 id 路径完全相同——
   2026-10-16 的启动崩溃即由此而来（两张分页卡的翻页箭头共用 `("np-arrow", 图标)`）。
2. **循环渲染的元素 id 必须含条目唯一键**（`format!("playlist-track-{}", song.id)`），
   不要只用类型或**可变下标**：类型必然重复，下标在列表重排后会把状态归属搞错。
3. **风险只在同一 view 的兄弟子树之间**：`ViewElement` 会把 `ElementId::View(entity_id)` 压栈，
   不同 `Entity`（页面、组件）之间天然隔离，跨页面同名 id（如 `nav-back`）不会冲突。
4. 定位手段：debug 构建会 panic 并给出重复的 node id；要拿到「首次出现位置」需临时给 gpui 的
   `A11yNodeBuilder::can_push` 补打 `node_info`（`element_id` / `source_location`），
   再 `cargo clean -p gpui-pre` 强制重建。

## 8. 检查表（评审用）

- [ ] 新增状态是否放在了最窄的 owner？
- [ ] 是否存在同一值的第二个副本？
- [ ] 全局变化后需要重绘的地方是否 `notify` / `observe_global`？
- [ ] 异步回调是否判代，避免旧响应覆盖新状态？
- [ ] `render` 是否保持声明式、无副作用、无条件 notify？
- [ ] 落盘键是否归属到 `SettingsStore`/`Session`？
- [ ] 新增卡片/面板容器是否有 id？循环项的元素 id 是否含条目唯一键（而非可变下标）？
