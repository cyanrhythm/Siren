# 02 · 平台能力规格

> 本文定义 `siren-platform` 的平台能力 trait。
> 这些 trait 的**职责划分继承自 Melodia 桌面端的接口设计**（`platform/native/`），
> 是经过实际踩坑验证后的结果——包括哪些能力该抽象、哪些不该。

---

## 0. 设计原则

1. **接口只描述"做什么"，不描述"怎么做"**
   例如 `MediaSession` 只声明"同步元数据/接收指令"，不暴露 SMTC 或 MPRIS 的概念。

2. **能由 crate 解决的不抽象成 trait**
   托盘、自启、热键、目录均有成熟跨平台 crate，直接使用，无需自建 `TrayIntegration` 等抽象。
   仅当需要精细控制（如托盘菜单原生渲染）时才考虑薄封装。

3. **平台差异只允许在实现层**
   trait 本身位于 `siren-platform/src/*.rs`，实现位于 `windows/`、`linux/`、`macos/`。

4. **同步接口保持简单，异步用 `async fn`**
   平台调用多数是阻塞的，由调用方决定是否放入线程池。

## 1. 能力清单与选型对照

| Melodia 接口 | Siren 处理方式 | 理由 |
|---|---|---|
| `AppPaths` | 用 **`directories`** crate | Rust 有官方推荐 crate，无需自建 |
| `AutoStartManager` | 用 **`auto-launch`** crate（Tauri 出品） | 跨平台封装完善 |
| `GlobalHotkeyService` | 用 **`global-hotkey`** crate（Tauri 出品） | 覆盖三平台 |
| `TrayIntegration` | 用 **`tray-icon`** crate（Tauri 出品） | 封装了 SNI / Shell_NotifyIcon / NSStatusItem |
| `SystemMediaSession` | **`playwire`**（首选）或 `zbus` 自研 | 无可靠 crate 时自研；见 §3 |
| `NativeLibraryLocator` | 由 libmpv 绑定的加载逻辑处理 | 库名/搜索路径差异已在绑定层 |
| `WindowDecoration` | GPUI 自带 + 平台薄封装（可选 `window-vibrancy`） | 见 §4 |
| `SystemAccentProvider` | 读配置文件 / 系统 API | 见 §5 |
| `DesktopLyricBehavior` | X11 输入区域 / 窗口 flags | 见 §6 |
| `UiScale` | GPUI 自带 HiDPI 处理 | 见 §7 |
| **通知**（新增） | 平台分支：`tauri-winrt-notification` / `notify-rust` | 见 §11 |

> **关于 Tauri 生态**：上表中标注"Tauri 出品"的 crate **均不依赖 Tauri 运行时**，
> 可独立使用。Tauri 的 `tauri-plugin-*` 系列**不可用**（依赖运行时），
> 但多数有等价的底层 crate。完整评估见
> [`03-技术选型.md § 10`](03-技术选型.md#10-tauri-生态-crate-评估)。

## 2. 目录能力（用 crate）

**选型**：`directories` crate（即 `directories-jvm` 的 Rust 原版）

```rust
use directories::ProjectDirs;

let dirs = ProjectDirs::from("com", "cyanrhythm", "Siren").unwrap();
dirs.config_dir();   // Windows: %APPDATA%\Siren
                     // Linux:   ~/.config/siren
                     // macOS:   ~/Library/Application Support/com.cyanrhythm.Siren
dirs.cache_dir();    // Windows: %LOCALAPPDATA%\Siren\cache
                     // Linux:   ~/.cache/siren
```

> **注意**：Melodia 曾评估 `directories-jvm` 后决定不用（因其在 Windows 上多插一层目录，
> 会破坏已有用户的升级路径）。Siren 是全新项目，**无历史包袱**，可直接采用。
> 详见 [`04-迁移规格.md`](04-迁移规格.md#2-曾经的选型否决及其理由)。

**派生目录约定**（与 Melodia 一致）：

| 用途 | 相对位置 |
|---|---|
| 日志 | `data_dir/logs/` |
| 配置/偏好 | `data_dir/` |
| 图片缓存 | `cache_dir/image_cache/` |
| 音频缓存 | `cache_dir/audio_cache/` |
| 元数据缓存 | `cache_dir/meta_cache/` |
| 下载临时 | `cache_dir/download_tmp/` |
| 默认下载目录 | `~/Music/Siren/` |

## 3. 系统媒体控制（核心能力）

### 3.1 需求（继承自 Melodia 的实际实现）

| 需求 | 说明 |
|---|---|
| 元数据同步 | 标题、歌手、专辑、封面 URL、时长 |
| 播放状态 | Playing / Paused / Stopped |
| 进度同步 | 当前位置与总时长；带跳转检测 |
| 模式同步 | 循环（单曲/列表）、随机 |
| 指令接收 | 播放、暂停、上一首、下一首、定位、循环/随机切换 |
| 可用性探测 | 无可用后端时降级，不影响其他功能 |

### 3.2 平台对应

| 平台 | 后端 | 备注 |
|---|---|---|
| Windows | **SMTC** | `SystemMediaTransportControls`（WinRT） |
| Linux | **MPRIS 2**（D-Bus） | 需实现 `MediaPlayer2` 与 `MediaPlayer2.Player` |
| macOS | **MPNowPlayingInfoCenter** | 需接入 MediaPlayer 框架 |

### 3.3 trait 设计

```rust
/// 系统媒体控制会话。
/// 平台实现由 cfg 在编译期选择。
pub trait MediaSession: Send + Sync {
    /// 后端是否可用
    fn is_available(&self) -> bool;

    /// 初始化，返回是否成功
    fn start(&mut self) -> bool;

    /// 启停（禁用时不应影响播放本身）
    fn set_enabled(&mut self, enabled: bool);

    /// 元数据变更
    fn set_metadata(&self, meta: &MediaMetadata);

    /// 播放状态变更
    fn set_playback_status(&self, status: PlaybackStatus);

    /// 进度变更（位置与时长，单位毫秒）
    fn set_timeline(&self, position_ms: u64, duration_ms: u64);

    /// 循环 / 随机模式
    fn set_play_mode(&self, mode: PlayMode);

    /// 注册指令回调（由用户按媒体键或点击系统卡片触发）
    fn set_command_handler(&self, handler: Box<dyn Fn(MediaCommand) + Send + Sync>);

    /// 释放资源
    fn shutdown(&self);
}

pub enum MediaCommand {
    Play,
    Pause,
    Toggle,
    Next,
    Previous,
    SeekTo(u64),       // 绝对位置（毫秒）
    SeekBy(i64),       // 相对偏移（毫秒）
    SetRepeat(bool),   // true = 单曲循环
    SetShuffle(bool),
}
```

### 3.4 Linux MPRIS 实现要点（血泪经验）

> 以下均来自 Melodia 在真实 KDE 环境踩过的坑，**换语言后依然适用**。

| # | 要点 | 后果 |
|---|---|---|
| 1 | **先导出对象，再抢总线名** | KDE 的 libkmpris 监听 `NameOwnerChanged`，名称一出现就立即 `GetAll`。若对象尚未导出，首次抓取失败 → **播放器被永久忽略**（表现为能播放但媒体中心无卡片） |
| 2 | **必须实现 `MediaPlayer2` 根接口** | 缺失 `Identity` / `DesktopEntry` / `CanQuit` / `CanRaise` 等会被部分宿主忽略 |
| 3 | **必须提供 `CanPause` / `CanStop`** | KDE 的暂停按钮会先读 `CanPause`，**缺失时直接短路**，根本不发出 D-Bus 调用 |
| 4 | **`mpris:trackid` 必须是对象路径** | 类型为 `o`，不是字符串。用错会导致元数据整体被忽略 |
| 5 | **`xesam:artist` 是字符串数组** | 类型 `as`，不能用单个字符串 |
| 6 | **`mpris:length` 是微秒** | int64，非毫秒 |
| 7 | **主动推送 `PropertiesChanged`** | 否则宿主只能轮询，卡片刷新明显滞后 |
| 8 | **`Set` 要接受 `LoopStatus` / `Shuffle`** | 宿主会尝试写入，需映射到播放模式 |

**DBus 类型签名速查**：

| 字段 | 签名 | 值类型 |
|---|---|---|
| `mpris:trackid` | `o` | object path |
| `mpris:length` | `x` | int64（微秒） |
| `mpris:artUrl` | `s` | string |
| `xesam:title` | `s` | string |
| `xesam:artist` | `as` | string array |
| `xesam:album` | `s` | string |
| `Metadata` 整体 | `a{sv}` | dict |

### 3.5 crate 评估：playwire

| 指标 | 数值 | 判断 |
|---|---|---|
| 最新版 | 2.0.0 | 较新 |
| 总下载 | 3,050 | **偏少** |
| 维护者 | 个人 | 单人维护 |

**风险**：下载量意味着实际场景验证不足，而上表 8 条坑**都可能未覆盖**。

**建议**：
1. **先用 playwire 做 PoC**，重点验证 §3.4 的 8 条
2. **备胎方案**：`zbus`（Rust 的 D-Bus 库，极其成熟）+ 自研 MPRIS 接口
   - 工作量约 300–400 行
   - Melodia 已有 Kotlin 实现（371 行）**可逐行对照移植**
   - 因已知全部坑点，自研反而可能比赌冷门 crate 更稳

## 4. 窗口装饰

**处理方式**：优先使用 GPUI 自带的窗口装饰能力；平台特殊效果做薄封装。

| 平台 | 能力 | 说明 |
|---|---|---|
| Windows | DWM 圆角、边框色、最小化动画 | 需 `dwmapi` 调用 |
| Linux | 交给窗口管理器 / CSD | **不建议**自行干预 |
| macOS | 系统原生装饰 | 一般无需干预 |

**原则**：装饰类能力**不应阻塞核心功能**。缺失时降级为默认外观即可。

### 4.1 可选：`window-vibrancy`（Tauri 出品）

为窗口施加系统级半透明/模糊（Windows Acrylic/Mica、macOS 毛玻璃）。

| 项 | 说明 |
|---|---|
| 依赖 Tauri 运行时 | ❌ 无 |
| 下载量 | 23,585,984 |
| Linux 支持 | ❌ 不支持（返回 `UnsupportedPlatform`） |

⚠️ **需验证**：GPUI 自行管理窗口，而 `window-vibrancy` 需要**原生窗口句柄**。
若 GPUI 未暴露获取句柄的接口，则无法接入。

**定位**：P2 可选增强，验证不通过则放弃，不影响主体功能。
详见 [`03-技术选型.md § 7`](03-技术选型.md#7-窗口特效window-vibrancy-)。

## 6. 桌面歌词窗口

这是**平台差异最大**的能力，需按平台与会话类型分支。

| 场景 | 方案 | 可行性 |
|---|---|---|
| X11 | `XShape` 扩展清空输入区域 | ✅ 可实现 |
| Wayland 原生 | **无协议支持** | ❌ 不可实现，降级为置顶不穿透 |
| Windows | `WS_EX_TRANSPARENT \| WS_EX_LAYERED` | ✅ |
| macOS | `NSWindow.ignoresMouseEvents` | ✅ |

**关键事实**：Wayland 出于安全设计**不允许**客户端设置输入穿透。任何 GUI 工具包（含 GPUI）都受此限制。

**降级策略**：Wayland 下窗口置顶显示但可点击，并在设置页说明限制。

## 7. UI 缩放（HiDPI）

**Melodia 的问题**：JVM/AWT 在 Linux 上只支持整数缩放（`1.5` 被静默忽略），
而 KDE 等桌面常见 125% / 150%，导致界面偏小，需自行探测并补偿。

**Siren 的优势**：GPUI 原生处理 HiDPI，**预计无需自建探测逻辑**。
但仍需在 PoC 阶段验证 KDE 分数缩放下的实际表现。

## 8. 全局快捷键

**选型**：`global-hotkey` crate（Tauri 出品）

| 平台 | 底层 |
|---|---|
| Windows | `RegisterHotKey` |
| Linux (X11) | `XGrabKey` |
| Linux (Wayland) | 依赖 XDG Portal（`GlobalShortcuts`） |
| macOS | `CGEventTap` |

**Wayland 限制**：Portal 的全局快捷键需用户经桌面环境授权，且并非所有 DE 都实现。
降级策略：依赖系统媒体键（MPRIS 已能接收），自定义热键不可用。

## 9. 托盘

**选型**：`tray-icon` crate

| 平台 | 底层 |
|---|---|
| Windows | `Shell_NotifyIcon` |
| Linux | StatusNotifierItem（SNI over D-Bus），回退 XEmbed |
| macOS | `NSStatusItem` |

**Melodia 的经验**：
- Wayland 下 XEmbed 图标**收不到鼠标事件**（KDE 的 `xembedsniproxy` 把点击转成合成 X11 事件），且**不吃 alpha**（圆角外填白）
- 因此 Linux 应优先走 **SNI**，由托盘宿主直接回调 `Activate` / `ContextMenu`
- `tray-icon` 已封装这些差异，理论上无需自己处理

## 10. 音频引擎

**选型**：libmpv

**需求**（继承自 Melodia）：

| 需求 | mpv 能力 |
|---|---|
| 流式播放（HTTP） | 原生支持 |
| **边播边录制缓存** | `stream-record` 选项，落成文件 |
| 精确 seek | `seek` 命令 |
| 多音频设备选择 | `audio-device-list` / `audio-device` |
| 宽格式兼容 | 底层 FFmpeg |
| **交叉淡入**（双实例） | 需跑两个 mpv 实例做音量 ramp |

**待验证**：
- Rust 侧 libmpv 绑定的成熟度
- `stream-record` 在 Rust 绑定中是否可用
- 双实例交叉淡入的资源开销

## 11. 系统通知

> Melodia 桌面端未实现通知，此处为 Siren 新增能力。

### 需求场景

| 场景 | 必要性 |
|---|---|
| 切歌提示（可关闭） | P2 |
| 登录失效提醒 | P2 |
| 下载完成 | P3 |
| 更新可用 | P3 |

### 平台方案

| 平台 | crate / API |
|---|---|
| Windows | [`tauri-winrt-notification`](https://crates.io/crates/tauri-winrt-notification)（WinRT Toast）<br/>⚠️ 官方描述为 "An incomplete wrapper" |
| Linux | [`notify-rust`](https://crates.io/crates/notify-rust)<br/>走 `org.freedesktop.Notifications`（D-Bus，与显示协议无关） |
| macOS | `notify-rust`，或用 `objc2` 绑定 `UNUserNotificationCenter` |

### trait 设计

```rust
pub trait Notification {
    /// 后端是否可用
    fn is_available(&self) -> bool;

    /// 发送通知；返回通知 id（用于后续更新或关闭）
    fn notify(&self, title: &str, body: &str, icon: Option<&[u8]>) -> Option<u64>;

    /// 关闭指定通知
    fn close(&self, id: u64);
}
```

**降级策略**：不可用时静默忽略，或用应用内浮层提示。
