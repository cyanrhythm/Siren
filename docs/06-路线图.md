## 阶段 0 · PoC 验证

**目标**：清除所有 P0 级技术风险，确认方案可行。

**产出**：一个能"出声 + 有托盘 + 有媒体控制"的最小应用。

| 任务 | 验收 |
|---|---|
| gpui-kit 脚手架 | 三平台能编译出可运行窗口 |
| libmpv 集成 | 播放一个本地音频文件 |
| playwire 集成 | KDE 媒体中心显示卡片、暂停按钮有效 |
| `tray-icon` 集成 | 托盘图标显示、点击有响应 |
| `directories` 集成 | 三平台路径正确 |

**详见** [`05-PoC验证清单.md`](05-PoC验证清单.md) 与
[`07-开发计划.md § 1`](07-开发计划.md#1-阶段-0--poc-验证详细步骤)（含执行顺序）

**关键决策点**：
- playwire 是否采用（否则切 zbus 自研）
- libmpv 绑定选择

> ⚠️ **本阶段结束前不要开始 UI 开发** —— 若 gpui-kit 或 libmpv 不满足，方案需调整。

## 阶段 1 · 核心播放

**目标**：能搜索、能登录、能播放网易云音乐。

| 模块 | 内容 |
|---|---|
| **网络层** | HTTP 客户端、请求签名（WeApi/EApi 加密） |
| **认证** | 扫码登录 / Cookie 登录 |
| **API** | 搜索、歌曲详情、播放地址获取 |
| **播放控制** | 队列、播放/暂停、上下一首、seek、模式切换 |
| **音频引擎** | libmpv 封装（加载、播放、事件回调、设备选择） |
| **基础 UI** | 主窗口、播放条、搜索页、登录页 |
| **状态管理** | 播放状态流、订阅机制 |

**里程碑**：`能登录、搜到歌、播放并控制`

> 可量化验收标准见 [`07-开发计划.md § 4`](07-开发计划.md#4-里程碑验收标准可量化)

**技术重点**：
- 网络加密需对照 Melodia 实现重写，用其测试用例作验收
  （见 [`04-迁移规格.md § 5`](04-迁移规格.md#5-网络层规格)）
- 注意 RSA 模数的**修正值**（Melodia 源码有注释指出历史拼写错误）

## 平台优先级

| 平台 | 优先级 | 说明 |
|---|---|---|
| **Linux** | 🎯 **主要开发目标** | 相对 JVM 方案优势最大；原生适配 XDG / MPRIS / SNI |
| **Wayland** | 🎯 **Linux 下的优先会话** | 新会话且能力受限最多，**先摸清再补 X11** |
| Windows | 次要 | 用户覆盖广，平台能力较标准化 |
| macOS | 暂缓 | 阶段 4 再补 |

**「Wayland 优先」的三条含义**：

1. **新功能先在 Wayland 下验证**，再补 X11
2. **受协议限制的能力明确降级**（全局快捷键、点击穿透），不为其妥协架构
3. 托盘与媒体控制走 **D-Bus**，两种会话下表现一致

> 详见 [`01-架构设计.md § 5`](01-架构设计.md) 与
> [`02-平台能力规格.md § 6、§ 8`](02-平台能力规格.md)。

## 风险与应对

| 风险 | 阶段 | 应对 |
|---|---|---|
| gpui-kit 无法打包 | 0 | 尽早验证；备选 `iced` |
| libmpv 无 `stream-record` | 0 | 自写绑定；或牺牲该功能 |
| playwire 不满足 | 0 | 切 `zbus` 自研（有参照实现） |
| **加密调试成本高** | 1 | 用 Melodia 测试用例逐项校验；预留充足时间 |
| **GPUI 生态不成熟** | 1-3 | 缺第三方组件需自绘；接受 UI 适当简化 |
| **GPUI 状态模型差异大** | 1 | 与 Compose 心智不同；先读 coding-guides |
| Wayland 托盘无响应 | 2 | 降级或依赖系统媒体键 |
| libmpv 分发复杂 | 0-4 | 阶段 0 就验证；优先自带精简构建 |

> 风险详述见 [`07-开发计划.md § 5`](07-开发计划.md#5-补充风险06-路线图md-未列)。

## 工作量量级

| 模块 | 相对 Melodia | 说明 |
|---|---|---|
| 可直接移植（加密、歌词、算法） | ~25% | 有"标准答案"，可对照 |
| 需重写（UI） | ~50% | Compose → GPUI，**最大工作量** |
| 需重做（平台层） | ~15% | 但有 crate 助力，反而省力 |
| 全新（GPUI 生态） | ~10% | 状态管理、组件自绘 |

> **总计**：Siren ≈ Melodia 桌面端 **70-80%** 的工作量。
> 详细测算见 [`07-开发计划.md § 3`](07-开发计划.md#3-工作量量级评估)。

**两点关键判断**：

1. **UI 是最大工作量**（占比过半），且无法复用
2. **网络层是最大风险** —— 量不算最大，但**调试成本高**（加密写错很难定位）
