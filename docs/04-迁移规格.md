# 04 · 迁移规格

> 本文汇总从 Melodia（Kotlin/Compose 桌面端）继承的**功能需求**与**踩坑记录**。
> 这些经验**与实现语言无关** —— 换到 Rust 后同样适用，是 Siren 的规格来源。

## 2. 曾经的选型否决及其理由

> 这些否决**对 Melodia 成立，对 Siren 可能不成立**——因为约束条件不同。

### 2.1 `directories-jvm` 被否决

**Melodia 的否决理由**：
`ProjectDirectories` 会在项目路径下**多插一层** `data/`：

| 项 | Melodia 现有 | directories 输出 |
|---|---|---|
| 数据 | `%APPDATA%\Melodia` | `%APPDATA%\Melodia\data` |

已有用户的登录态在旧路径，换库后程序读不到 → 等于"数据全丢"，需额外迁移逻辑。

**对 Siren 的结论**：✅ **可以採用**。Siren 是全新项目，无历史数据，无升级路径问题。

### 2.2 桥接 Qt/GTK 被否决

**结论**：**不可行**。

**理由**：X11 与 Wayland 的差异源于 **Wayland 协议本身**，而非工具包实现：

| 能力 | X11 | Wayland |
|---|---|---|
| 全局热键 | ✅ `XGrabKey` | ❌ 无协议 |
| 窗口点击穿透 | ✅ XShape | ❌ 无协议 |
| 获取他人窗口句柄 | ✅ | ❌ 明确禁止（安全设计） |

GTK/Qt 运行在 Wayland 下**受同一套约束**——它们的 `set_pass_through()` 同样静默失效。

**对 Siren 的结论**：✅ **同样适用**。GPUI 也受 Wayland 协议限制，
**必须按会话类型分支 + 明确降级**，不能指望框架抹平。

## 3. 平台踩坑记录（跨语言有效）

### 3.1 Linux MPRIS（8 条）

详见 [`02-平台能力规格.md § 3.4`](02-平台能力规格.md#34-linux-mpris-实现要点血泪经验)。

摘要：

| # | 要点 | 后果 |
|---|---|---|
| 1 | **先导出对象，再抢总线名** | 否则 KDE 首次 `GetAll` 失败 → 播放器被永久忽略 |
| 2 | 实现 `MediaPlayer2` 根接口 | 缺失会被部分宿主忽略 |
| 3 | 提供 `CanPause` / `CanStop` | KDE 读不到会**短路**，不发 D-Bus 调用 |
| 4 | `mpris:trackid` 用对象路径类型 `o` | 用错则元数据整体被忽略 |
| 5 | `xesam:artist` 用字符串数组 `as` | 用单字符串无效 |
| 6 | `mpris:length` 用微秒 | 非毫秒 |
| 7 | 主动推送 `PropertiesChanged` | 否则卡片刷新滞后 |
| 8 | `Set` 接受 `LoopStatus` / `Shuffle` | 宿主会尝试写入 |

### 3.2 Linux 托盘（SNI vs XEmbed）

**Melodia 的发现**：

| 方式 | 问题 |
|---|---|
| XEmbed | Wayland 下经 `xembedsniproxy` 桥接，**收不到鼠标事件**（点击被转成合成 X11 事件）；且**不吃 alpha**（图标圆角外填白） |
| SNI | 托盘宿主直接回调 `Activate` / `ContextMenu`，点击可靠；`IconPixmap` 支持透明 |

**结论**：Linux 优先 SNI。

**对 Siren 的结论**：`tray-icon` 已封装此差异，理论上无需自己处理，但**仍需在 KDE Wayland 下实测验证**。

### 3.3 X11 输入穿透

| 场景 | 方案 | 可行性 |
|---|---|---|
| X11 / XWayland | `XShape` 扩展清空输入区域 | ✅ |
| Wayland 原生 | 无对外协议 | ❌ 降级为置顶不穿透 |

**Melodia 的实现**：遍历窗口树找到 X11 Window ID → `XShapeCombineRectangles` 设为空区域。

**对 Siren 的结论**：GPUI 应用需拿到原生窗口句柄，再调用 `x11rb` 或 `xcb` 设置输入区域。

### 3.4 Linux 分数缩放

**Melodia 的问题**：
JVM/AWT 在 Linux 上**只支持整数缩放**（`sun.java2d.uiScale` 的分数值被静默忽略，
实测 1.5 无效、2 生效），而 KDE 常见 125% / 150%，导致：
- `GraphicsConfiguration` 的 `defaultTransform` 恒为 1.0
- Compose 的 `LocalDensity` 随之 = 1.0
- **界面偏小**

**Melodia 的解法**：自行探测（Wayland 用 `WAYLAND_DISPLAY` 等环境变量，
X11 读 `Xft.dpi`），再手动补偿。

**对 Siren 的结论**：GPUI 原生处理 HiDPI，**预计无需自建**。但需在 PoC 阶段验证 KDE 分数缩放。

### 3.5 音频设备过滤

**Melodia 的问题**：mpv 的 `audio-device-list` 会混入其他后端的泛称条目（如 `openal`）。

| 平台 | 处理 |
|---|---|
| Windows | 只保留 WASAPI 设备（`wasapi/` 前缀） |
| Linux | 应按当前声音服务过滤（`pipewire/` / `pulse/` / `alsa/`），**不能照搬 WASAPI 逻辑** |

**对 Siren 的结论**：同样适用，需按平台分支。

### 3.6 libmpv 加载

**Melodia 的要点**：
- Windows：`libmpv-2.dll`，需 `addSearchPath` 注册资源目录
- Linux：依次尝试 `libmpv.so.2` → `libmpv.so` → 系统库 `mpv`
- **失败时降级**：捕获 `LinkageError`，回退到"不出声的占位实现"，界面仍可用

**对 Siren 的结论**：Rust 侧同样需要**优雅降级**——libmpv 缺失不应导致应用崩溃。

## 5. 网络层规格

### 5.1 需重写的部分

网易云 API 的请求需要加密，Melodia 的实现位于 `:shared` 模块：

| 组件 | 说明 | 复杂度 |
|---|---|---|
| **WeApi 加密** | AES + RSA 混合 | 中 |
| **EApi 加密** | 另一套 AES 方案 | 中 |
| **LinuxApi 加密** | 第三套方案 | 中 |
| 设备 ID 生成 | 客户端标识 | 低 |
| 请求拦截器 | 加密参数注入 | 低 |

**关键算法**（Melodia 的 `NeteaseCrypto.kt`）：
- AES-CBC，固定 IV `0102030405060708`
- 预设密钥 `0CoJUm6Qyw8W8jud`（首次加密）
- 随机 16 位密钥（二次加密）
- RSA 公钥 `010001` + 特定模数

> ⚠️ **注意**：Melodia 的实现中有一个**修正过的 RSA 模数**
> （源代码注释指出"原有的模数尾部存在拼写错误导致解密失败"）。
> Rust 重写时需确保使用正确值。

### 5.2 复用策略评估

| 方案 | 说明 | 评估 |
|---|---|---|
| **对照重写** | 用 Rust 的 `aes` / `rsa` crate 实现 | 🟢 推荐。逻辑清晰，约 200–300 行 |
| **FFI 桥接** | 编译 `:shared` 为 native 库调用 | 🟡 会引入 JVM 或 GraalVM Native Image 复杂度，违背"轻量原生"目标 |
| 直接调用 API | 不加密 | ❌ 不可行 |

**建议**：对照重写。加密逻辑是**纯计算**，无平台依赖，且有现成测试用例
（`NeteaseCryptoTest.kt` / `XeapiCryptoTest.kt`）可作为**验收标准**。

## 6. 不迁移的内容

| 内容 | 原因 |
|---|---|
| Android 端（`:app`） | 本项目仅面向桌面 |
| Compose UI 代码 | GPUI 与 Compose 差异大，需重写 |
| KSP 处理器 | Rust 用条件编译，无需此机制 |
| AIDL（SuperLyric 协议） | Android 专有；如需系统歌词广播，需另寻方案 |
| 听歌识曲 | 复杂度高（音频指纹），非核心，暂不纳入 |
| 移动端适配逻辑 | 仅桌面 |

## 7. Melodia 资产的可用性

| 资产 | 位置 | 对 Siren 的价值 |
|---|---|---|
| 平台接口定义 | `platform/native/*.kt` | ⭐ **直接转为 trait** |
| MPRIS 实现 | `linux/LinuxSystemMediaSession.kt`（371 行） | ⭐ 自研时逐行对照 |
| libmpv 集成 | `player/mpv/`（含 `MpvEnginePair`、`AudioCache`） | ⭐ 交叉淡入与流录制的参照实现 |
| 加密实现 | `core/network/crypto/` | ⭐ 对照重写 + 测试用例作验收 |
| 歌词解析 | `player/domain/`（LRC/QRC/TTML） | ⭐ 纯逻辑，可对照移植 |
| 平台踩坑记录 | 上述提交历史、ADR、审计文档 | ⭐ **规格来源** |
| Compose UI | `ui/`（约 15,000 行） | ❌ 需重写（设计可参考） |
